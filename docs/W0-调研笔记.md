# DshDeck W0 · ACP 调研笔记

> 实测时间：2026-09-24/25 · dsh **0.1.7-rc.1** · 命令 `dsh --profile acp` · 探针 `probe/acp-probe.mjs` 及 `probe/acp-probe-*.mjs`  
> 原始轨迹：`docs/W0-acp-trace.jsonl`、`docs/W0b-acp-trace.jsonl`

## 1. 传输

- stdio，**换行分隔 JSON-RPC 2.0**
- Windows 下 spawn 需 `shell: true` 调 `dsh`（或完整 `dsh.cmd` 路径）
- 启动到 `initialize` 返回约 **3.3s**（冷启动）；后续方法 <100ms

## 2. 已验证方法

| 方法 | 参数（实测可用） | 结果 |
|---|---|---|
| `initialize` | `{ protocolVersion: 1, clientCapabilities: { fs: { readTextFile, writeTextFile } }, clientInfo: { name, version } }` | `protocolVersion`、`agentInfo`、`agentCapabilities` |
| `initialized` | notification `{}` | 发出后即可调 session API |
| `session/new` | `{ cwd, mcpServers }` | `sessionId`、`configOptions[]` |
| `session/list` | `{}` | `{ sessions: [{ sessionId, cwd }] }` |
| `session/prompt` | `{ sessionId, prompt: [{ type: "text", text }] }` | 异步流式通知 + 最终 `{ stopReason }` |
| `session/cancel` | **notification**（无 id）：`{ jsonrpc: "2.0", method: "session/cancel", params: { sessionId } }` | 见 §5e——带 id 调用会 `Method not found` |
| `session/set_config_option` | `{ sessionId, configId, value }`（**注意是 `configId`，非规范上的 `configOptionId`**） | 返回**更新后的完整 configOptions**，可作 UI 状态真值 |
| `session/close` | `{ sessionId }` | `{}` |

## 3. initialize 回包（摘要）

```json
{
  "protocolVersion": 1,
  "agentInfo": { "name": "deepseek-harness-acp", "version": "0.0.1" },
  "agentCapabilities": {
    "mcpCapabilities": { "http": true },
    "promptCapabilities": { "image": false, "audio": false, "embeddedContext": false },
    "sessionCapabilities": { "close": {}, "list": {}, "resume": {} }
  },
  "authMethods": []
}
```

完整字段见 trace 中 `initialize` 的 `result`。

## 4. session/new 回包

- `sessionId`: UUID（本连接内；历史 id 也有 `session-<uuid>` 形态）
- `configOptions[]`（**模型/思考强度可直接绑定**）：
  - `model`：`select`，`options[]` 可嵌套 `group`（如 deepseek-official → deepseek-v4-flash / DeepSeek-V41-Flash / DeepSeek-V4-Pro）
  - `reasoning_effort`：`select`，`off | low | high | max`（默认 `high`）
- `agentCapabilities.sessionCapabilities` 含 **`resume`**

## 5. 通知（session/update）

| sessionUpdate | 字段 |
|---|---|
| `agent_message_chunk` | `messageId`, `content: { type: "text", text }` |
| `agent_thought_chunk` | 同上（思考流） |
| `tool_call` | `toolCallId`, `title`, `kind`, `status: "in_progress"`, `rawInput` |
| `tool_call_update` | `toolCallId`, `status: "completed"\|…`, `content: [{ type: "content", content: { type: "text", text } }]` |
| `usage_update` | `used`, `size` |

→ TAO：`agent_thought_chunk` → 思考折叠；`tool_call(_update)` → 工具卡；`agent_message_chunk` → 正文。

## 5b. session/resume（已实测）

```text
session/resume  { sessionId, cwd }  →  { sessionId?, configOptions, ... }
```

- **历史** id（`session-<uuid>`）+ 原 `cwd` 可 resume
- 当前连接 **active** 会话 resume → `Invalid params: session is already active`
- 少参数（仅 sessionId）→ `Invalid params`

## 5c. permission

- 当前 `acp` profile 下 `write` / `pwsh` / agent 主动创建文件**均不弹 permission**（直接执行成功）——W0b 再次用「请创建 _perm_probe.txt」实测，agent 直接写盘，60s 内无任何 `session/request_permission`
- 结论：形状采集被 profile 策略阻塞；壳侧审批卡按 ACP 规范实现（`params.options[].optionId` + `outcome.selected/cancelled` 回包），并带无选项降级，待收紧权限的 profile 出现后回归验证

## 5e. W0b 实测补充（2026-09-25，探针 `acp-probe-set.mjs` / `acp-probe-cancel-verify.mjs`）

1. **`session/cancel` 是通知不是请求**（与 ACP 规范一致，修正 §2 旧记录）：
   - 带 id 调用 → `"Method not found": session/cancel`
   - 以 notification 发送 → 流中 prompt **毫秒级** settle，`stopReason: "cancelled"`，会话继续可用（下一条 prompt 正常 `end_turn`）
   - **影响**：M1 壳内用 call 实现的 cancel 是坏的，已修复（双传输）
2. **configOptions set 通道打通**：
   - 方法：`session/set_config_option`，参数 `{ sessionId, configId, value }`（dsh 偏离规范的 `configOptionId`，穷举 7 种形状确认）
   - 返回更新后的完整 configOptions；**改 model 会把 reasoning_effort 重置回默认** → UI 先设 model 再设 effort，或以返回值为准重渲染
   - `session/new` 忽略初始 config 参数（三种变体均无效）——初始值必须在 session/new 之后 set
3. **model 的 value 是 JSON 字符串数组**：如 `["deepseek-official","deepseek-v4-flash"]`，options 内嵌 group 两层
4. configOptions 全量结构见 `docs/W0b-acp-trace.jsonl`（model / reasoning_effort，含 description）

## 5d. 约束

- 同一 session **同时只能一个 prompt**；未结束再发 → `a prompt is already in flight`
- 超时后必须 `session/cancel` 再发下一条

## 6. session/prompt

- 入参 `prompt` 为 **内容块数组**：`[{ type: "text", text }]`
- 纯文本问答约 **1.1s** 返回
- 回包：`{ stopReason: "end_turn" }`

## 7. session/list

- 历史会话 id 形如 `session-<uuid>`，与本连接 `session/new` 的 UUID 形态不同
- 仅返回 `sessionId` + `cwd`；回放格式仍待读 `~/.dsh/sessions/`

## 9. 对 M1 的直接结论

1. 竖切协议路径 **已通**：`initialize → initialized → session/new → session/prompt → 流式 session/update → stopReason → session/close`
2. UI 可先渲染 `agent_message_chunk` 文本流 + `usage_update` 进度
3. 模型下拉绑定 `configOptions`
4. Bridge 用 **严格类型 + 运行时校验** 解析 `session/update`，未知 `sessionUpdate` 原样进调试面板，不崩
